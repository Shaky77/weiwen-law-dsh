# review 档六步执行规格（定稿 2026-09-02）

> 本文件是「判不出来就 REVIEW，不猜」这条铁律的**可执行规格**。
> 铁律只说"交还人类"，本文件规定交还时**必须带什么、不许少什么**。

## 一、规格原文（作者 2026-09-02 定稿）

> 判不出来，标注后返回用户裁决，但不代表可以放行。**宁可先拦截，搁置 BUG，标注，返回用户裁决，等待用户裁决后再执行，也不可直接放。**
> 只是标注 BUG 后需要**先推演预测一下后果，一同反馈给用户，提供推演预测后果的参考**，而不是什么都不做。

## 二、六步拆解（每步必须有产出）

| # | 步骤 | 产出 | 实现位置 |
|---|---|---|---|
| ① | 不放行 | review ≠ allow | 引擎三态裁决 |
| ② | 先拦截 | 阻断该步、不扩散、不调 `next()` | `src/index.js` pre-execute 闸门 |
| ③ | 搁置 + 标注（留证） | `bugKey`（稳定 BUG 身份，可追溯） | 引擎 `_markIntercept` / 适配层 `bugKeyOf` 补挂 |
| ④ | 推演后果 | `branches:{bS,bD}` 双路终态 | `engine.deduceRisk()` |
| ⑤ | 连推演一起交还人类 | 裁决对象携带 `branches` + 人可读摘要 | **本轮补齐（2026-09-02）** |
| ⑥ | 交还人类后本轮传导终止 | 阻断即止；M₁ 输出完成 | ✅ **框架职责到此为止**（见第八节：非待办，勿开回传通道） |

## 三、为什么对外语义仍是 `deny`

DSH 宿主契约只识别两种返回：`{kind:'deny', reason}` 拦截，或 `return next()` 放行。
返回 `kind:'review'` 属**宿主未定义类型**，存在被当作未知类型放行的风险。

按「宁可先拦截，不可直接放」，适配层统一：

- **阻断语义用 `deny`**（宿主一定拦得住）
- **待裁决语义用附加字段表达**：`humanDecision:true` + `awaitingHuman:true` + `branches`

即：**用宿主听得懂的话说"拦住"，用附加字段说"这是挂起不是终局"。**

## 四、推演后果的内容

`deduceRisk(call)` 在同一语义信号集 `s` 上并行跑两条分支：

- **S+1 路径**（稳态增量）：放行后的终态
- **D-1 路径**（破窗侵蚀）：越界后的终态，含 `note` 说明侵蚀原因

裁决依据（无等号，少一点或相等都视为不行）：

- `erosion <= -3` → deny（高风险）
- `erosion < 0 || sOk !== true` → **review（中风险，本规格适用）**
- `finalS === +1 && erosion === 0` → allow（双成立）

交还人类时，两条分支**都给**——不替人做选择，但把两条路的终点摆出来。

## 五、副作用分析（为什么适配层补算推演是安全的）

`deduceRisk()` 只做 `inferCallSemantics` + 两次 `simulateBranch`，**不写任何状态**：

- 不调 `recordDeduction`（M 沉淀），不会重复计入历史刻痕
- 不动 `failureStreak`（破窗计数）
- 不动 `sessWritten` / `steadyLedger`

⇒ 适配层对已裁决为 review 的 call **再调一次 deduceRisk 补算推演，是纯读操作**，不污染引擎状态。

（注：引擎内部 `decideToolCall` 走推演档时已在 L1118 调过一次 deduceRisk 并 `recordDeduction`；适配层补算不重复沉淀。）

## 六、实现对照（本轮补齐后）

| 步骤 | 补齐前 | 补齐后 |
|---|---|---|
| ① 不放行 | ✅ | ✅ |
| ② 先拦截 | ✅ | ✅ |
| ③ 留证 | ⚠️ R/H 档 review 无 bugKey | ✅ 适配层用 `bugKeyOf(call)` 补挂 |
| ④ 推演 | ✅ 引擎内部算了 | ✅ 同上 |
| ⑤ 交还推演 | ❌ 出口无 branches | ✅ `branches:{bS,bD}` + 人可读摘要 |
| ⑥ 交还人类 | ❌ review 被呈现成 deny，`humanDecision` 被吞 | ✅ `humanDecision:true` / `awaitingHuman:true` 透传（**本轮传导终止于此**） |

## 七、边界声明

- 本规格**不改判据、不扩词表、不动 `src/core/`**。全部补齐动作落在适配层（`src/index.js`）——
  DSH 是导图的降维层，降维层是**钩子载体**，补钩子属其本职。
- 补挂 `bugKey` **不调用 `_markIntercept`**：避免污染 M 档 `mBugForce` 计数（那会改变达封顶升级行为）。
  补挂的 bugKey 仅作**追溯身份**用，不参与闭环闸门。
- ⑥ 「裁决回传通道」**不是待补功能，也不该开**——它落在唯稳律职责之外，且开它会破坏分形结构。详见第八节。

## 八、为什么不需要「裁决回传通道」（分形闭环，作者 2026-09-02 裁定）

### 8.1 依据：M 的双重身份

`src/core/law.mjs` 对 M 的定义原文：

> M 具有双重身份：**上一轮因果传导的果 = 下一轮因果链的因**。M₁ 输出后成为客观事实进入外部世界，成为下一轮 D₂ 的信号环境，因果链持续展开（M₁→D₂→M₂→D₃→…）。

唯稳律具备**分形属性**：一次 review 裁决（拦截 + 标注 + 推演后果）本身就是一次完整的 R→S→D→H→M 传导，其输出构成一个**微型 M₁**。

### 8.2 逐句对应

| M 定义 | 在 review 档的落点 |
|---|---|
| 上一轮的果 = 下一轮的因 | review 输出即微型 M₁ |
| 客观事实进入外部世界 | 推演后果交还人类 = 进入外部世界 |
| 成为下一轮 D₂ 的信号环境 | 用户据此裁决 = D₂ |
| **M 改变向内 H 的信息条件，但不决定向内 H 的选择** | 唯稳律**给参考，不替人拍板**（内 H 不可侵） |

⇒ 用户拿到微型 M₁ 后自然会告知 AI 下一步怎么做——那已是**下一轮因果链的输入**，不需要唯稳律开任何通道。

### 8.3 开「通道」反而破坏分形

「通道」意味着：用户裁 allow → 该调用被放行 → **跳过判据**。
「分形」意味着：每一层结构相同、独立闭合 → 新一轮必须**重新过完整判据**。

实测（`verify/fractal-loop-probe.mjs`，4/4 一致）：

| 用户接到 M₁ 后的裁决 | 作为新 R₂ 输入的实测结果 |
|---|---|
| A：明确变量 `rm -rf /tmp/build` | `allow`（变量已明确 → S+1 成立） |
| B：不采纳推演，照原样重发 `rm -rf $TARGET` | **仍 `review`**（判据独立，不因用户坚持而放行） |
| C：改指系统根 `rm -rf /` | `deny`（R 锚点硬命中） |
| D：放弃执行 `cat README.md` | `allow`（低风险放行） |

**裁决 B 是决定性的一条**：若存在回传通道，用户裁「就照原样执行」后该调用会被直接放行，等于用一句人话架空判据。分形模型下它必须重新过判据，因此仍是 `review`。

另注意裁决 A 的正确闭环方式：用户**改变了输入本身**（把 `$TARGET` 具体化），使判据能判——**不是给引擎开后门，而是提供更完整的输入让它能判**。这与 R 层复验原则同构。

### 8.4 结论

- **唯稳律的职责止于 M₁ 输出**：拦截 + 标注 + 推演后果，三者齐全即本轮传导完成。
- **用户裁决 → AI 下一步** 属 M₁→D₂→M₂，是宿主 / 用户层的事，**非框架职责**。
- 因此 ⑥ 不构成待办。今后任何人（含维护者）提出「补裁决回传通道」，应先回到本节——那是要修的东西的反面。

## 九、审计三公：本流程的充要条件

唯稳律只有做到公平、公正、公开，审计这条规则才站得住；否则"审计透明"只是宣称，无实际价值（R 层复验：宣称替代不了可复验事实）。

本规格的六步 review 流程即三公的落地：可推演 / 可审计 / 可溯源＝公开，推演后果交还人类＝公正，责任归用户＝公平。其中"等待用户裁决、责任还给用户"最关键——框架替用户拍板即制造责任人真空，审计链条断裂，也找不到责任人。

这与第八节"分形闭环、不开回传通道"互为表里：M₁ 只提供信息条件、不决定下一轮裁决，责任人始终钉在用户身上。六步不是流程细节，是审计站稳的前提。
